# Website launch checklist (approval gate)

- [ ] The lab director approves website copy, program brand, attribution and current affiliation.
- [ ] No project/paper/student/collaborator is listed without confirmed public-release rights and consent as appropriate.
- [ ] Institutional identities/logos comply with university policy; site does not imply official endorsement.
- [ ] Confirm GitHub repository owner, visibility and source rights before any push or Pages configuration.
- [ ] Inspect generated `index.html`, `styles.css`, scripts and source JSON for secrets, restricted data or drafts.
- [ ] Verify on mobile and desktop; inspect accessibility, links, titles and contact policy.
- [ ] Decide where to host (GitHub Pages as one option), review plan restrictions and public access.
- [ ] Only then approve public deployment; domain and DNS decisions are separate.
- [ ] Align copy with the awarded SIGNAL theme and confirm JMHC/Purdue naming rules (SIGNAL is a JMHC Interdisciplinary Research Generator); approve or replace the proposed methodological themes.
- [ ] Finish browser QA: 1440 px, 200–400% zoom, full keyboard order and screen-reader output (320/375/768/1024 px reflow and skip-link focus were checked on 2026-10-23; see `STATIC_REVIEW.md`).
- [ ] Deploy only an allowlisted artifact (`index.html`, `styles.css`, `assets/davi-moreira.jpg` and `.nojekyll`); keep `AGENTS.md`, `CLAUDE.md`, docs, tests and tools out of the published site.
- [ ] Record the actual GitHub plan and the separately approved site access mode; source-repository privacy is not access control for a Pages site.

All boxes remain unchecked; local tests are not deployment authorization.
